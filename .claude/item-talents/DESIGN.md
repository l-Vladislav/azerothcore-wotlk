# Item Talents — «Пробуждение снаряжения» (mod-item-talents)

Статус: **дизайн утверждён** (2026-07-06), реализация не начата.
Владелец: пока нет выделенного агента; SQL — через sql-migration-writer.

## 1. Концепция

У каждого предмета (оружие/броня) есть одна ветка «талантов» из 5 рядов.
Каждый ряд — выбор **1 из 3**. Прокачка идёт по **двум осям**:
**качество** предмета (GA) открывает ряды, **опыт предмета** (убийства,
пока вещь надета) даёт очки талантов; выбор в ряду стоит 1 очко.

| Качество | Открыто рядов | Ряд (ремесленный путь, утв. 2026-07-06) |
|---|---|---|
| Белый (1) | 1 | **Заточка** — флэт базовые статы (скейл от ilvl) |
| Зелёный (2) | 2 | **Закалка** — вторичные рейтинги (флэт, скейл от ilvl) |
| Синий (3) | 3 | **Гравировка** — утилити |
| Эпик (4) | 4 | **Насыщение** — синергия с системами сервера |
| Легендарный (5) | 5 | **Пробуждение** — уникальный прок (ФАЗА 2, только базовые эпики) |

Связка с Gear Ascension: GA-апгрейд качества = «уровень» предмета, открывающий
новый ряд. Выбор нижних рядов **сохраняется** при апгрейде. GA сейчас качает
только до эпика (tier III), поэтому ряд 5 приходит фазой 2 вместе с новой
ступенью GA (эпик → легендарка).

## 2. Принятые решения

- **Охват**: всё оружие и броня — worn-drops И стоковые предметы. Ключ — GUID
  предмета. Исключения: рубашки (InvType 4), гербовые накидки (19), наследие
  (quality 7), thrown (стакаются), удочки.
- **Две оси прокачки** (решение 2026-07-06, заменило «выбор бесплатный»):
  качество открывает РЯДЫ, опыт предмета даёт ОЧКИ. Стоковый эпик больше НЕ
  получает 4 выбора мгновенно — предмет надо отыграть (см. «Опыт предмета»).
- **Привязка**: первый вложенный талант делает предмет персональным
  (SetBinding), если он ещё не был привязан.
- **Респек**: бесплатно у мастера оружия, сброс любого ряда по отдельности
  (ряды независимы, каскадного сброса нет).
- **Специализация** (бонус за монотемный билд): НЕ делаем (решение 2026-07-06).
- **НПЦ**: мастера оружия (они же учат оружейным навыкам) обслуживают И оружие,
  И броню. Пункт меню «Пробудить снаряжение» добавляется хуком
  `AllCreatureScript::CanCreatureGossipHello` по списку entry из конфига.
- **UI** (обновлено 2026-07-06 после теста): аддон-панель в оболочке
  TransmogUI — кнопка на окне персонажа (рядом с кнопкой трансмога, -105/-41),
  слева колонка слотов экипировки, справа вертикальное дерево выбранного
  предмета; также /itu. Ctrl+ПКМ ОТМЕНЁН: обработчики кликов 3.3.5 биндятся
  к шаблону при загрузке XML, raw-замена глобала их не перехватывает.
  Без аддона — госсип у мастера. Просмотр — везде, выбор/сброс — только
  рядом с мастером.
- **Все значения — флэт** (решение 2026-07-06): никаких процентов в базовых
  статах, даже на 1-м ряду — игрок сразу видит изменение цифр. Проценты
  остаются только там, где стат по природе процентный (скорость бега,
  получаемое лечение, золото/опыт, урон по немезидам).
- **Проки 5-го ряда**: фаза 2.
- **Ряд 5 — только для базовых эпиков, открывается НА ЭПИКЕ** (финальное
  решение 2026-07-06, заменило требование легендарки): предметы с
  изначальным качеством 4 (стоковые рейд-эпики, worn-эпик дропы) открывают
  ряд 5 сразу на своём эпическом качестве; гейт — 5-е очко (4100 убийств).
  Предмет, поднятый GA до эпика с более низкой базы (белый нож -> эпик),
  ряд 5 НЕ открывает — его потолок 4 ряда. Определение базы: корень
  GA-цепочки (prev_entry до упора) либо не-GA предмет с Quality=4.
  Будущая ступень GA эпик->легендарка — чистый стат-апгрейд, рядов не
  добавляет. В панели у не-базовых эпиков ряд 5 помечается «недоступен
  для этого предмета» (HDR несёт флаг baseEpic).

### Роллы перков и качество (2026-07-06)

- Меню каждого ряда расширено до ~9-12 вариантов (PERKS.md), но предмет
  при получении **роллит 3 из них** — UI остаётся «выбор 1 из 3». Два
  одинаковых предмета получают разные наборы (ролл по GUID).
- **Ленивый ролл**: при первом обращении к предмету (EnsureState) — без
  роллов -> роллим и сохраняем. Покрывает все пути получения (лут, квест,
  почта, АХ, крафт) без десятка хуков.
- **Качество перка** — множитель значения: Обычный x1.0 (белый) /
  Отличный x1.25 (зелёный) / Совершенный x1.5 (фиолетовый), веса 70/25/5.
  Каждая ступень даёт МИНИМУМ +1 к предыдущей (2026-07-06):
  значение(q) = max(значение(q-1)+1, ceil(база x множитель)).
  Роллится на каждый из 3 слотов независимо. Конфиг
  ItemTalents.QualityWeights / QualityMults.
- Хранение: acore_characters.`item_talent_rolls`
  (item_guid, row, slot 1..3, choice, quality; PK item_guid+row+slot).
  item_talents.rowN теперь хранит выбранный СЛОТ (1..3), не choice.
- Ряды, где вариантов всего 3 (сейчас 3-4), роллят все 3 — поведение
  как раньше, но качество роллится и там.
- Миграция PTR-теста: если у предмета есть выбор, но нет роллов — роллим
  так, чтобы слот с прежним номером получил прежний choice (статы не едут).
- Идея на потом: «Свиток перековки» — ре-ролл одного ряда (экономика).

### Опыт предмета и очки талантов (2026-07-06)

- **Источник**: убийства владельца, пока предмет **надет**. Копится на ВСЕ
  надетые предметы одновременно — броня качается, пока её носишь.
  1 убийство = 1 прогресс, статично, БЕЗ множителей за элиту/боссов
  (источник помечен как предварительный — юзер ещё думает; на случай
  возврата к идее заложить конфиг ItemTalents.EliteMultiplier, по умолч. 1).
- **Считаются только убийства, приносящие опыт**: не-серые мобы, не криттеры,
  не питомцы. Чек — тот же, что для чести/XP (`Player::isHonorOrXPTarget`),
  он корректно работает и на 80-м уровне, где численно XP = 0.
- **Пороги очков** (эскалирующие, суммарные убийства): 1-е очко — 50,
  2-е — 200, 3-е — 600, 4-е — 1600, 5-е — 4100 (сегменты 50/150/400/1000/2500).
  Конфиг `ItemTalents.PointThresholds = "50,150,400,1000,2500"`. Значения —
  заготовка под тюнинг.
- **Уровни пробуждения** (решение 2026-07-06, заменило «общие очки»):
  ряд N доступен только с УРОВНЯ ПРОБУЖДЕНИЯ N — уровень = число
  достигнутых кумулятивных порогов убийств (50/200/600/1600/4100).
  Выбор в предыдущих рядах НЕ требуется (правило PREV_ROW опробовано
  ранее и отменено — не возвращать); ряд ждёт только свой уровень
  и качество. Сброс любого ряда, kills не сгорают. Поле freePts в HDR
  переосмыслено как уровень (0..5), протокол не менялся.
- **Сброс ряда** у мастера возвращает очко; убийства не сгорают.
- **GA-апгрейд**: kills/очки переносятся вместе с выборами на новый GUID.
- В сумке/банке опыт НЕ копится — только надетое.
- **Только PvE** (решение 2026-07-06): почётные PvP-убийства НЕ считаются.
  Для PvP возможно будет отдельный набор талантов — отложено на потом.
- **Боты исключены** (решение 2026-07-06): предметы плейерботов опыт НЕ
  копят. Конфиг ItemTalents.IgnoreBots = 1 (по умолчанию вкл).
- **v1 = ряды 1-2** (решение 2026-07-06): MaxImplementedRow = 2; ряды 3-4
  видны в панели, выбор закрыт «скоро». Пороги 50/200/600/1600/4100
  подтверждены как базовые, тюнинг после теста темпа на PTR.
- Опыт и выборы привязаны к конкретному предмету (GUID) — не к игроку.
- Открытый вопрос: live-обновление прогресс-бара при открытой панели.

## 4. Пулы талантов

Пул выбирается по (class, subclass) предмета. Значения: `N = ceil(ilvl × коэф)`.
Все коэффициенты ПРЕДВАРИТЕЛЬНЫЕ, тюнинг по факту.

- **A Ткань** — class 4, subclass 1 (включая плащи)

- **C Кольчуга** — class 4, subclass 3

### Балансовый якорь: «один талант ≈ один эпик-гем»

чтобы на ilvl 200 талант давал примерно один эпический самоцвет WotLK
(+30 вын. / +20 первичного стата / +40 АП / +23 СП / +20 рейтинга). Ниже
уровнем значения линейно меньше, но всегда ≥ 1 — видно даже на белом ilvl 5.

## 5. Бюджет стакинга

Слотов с талантами ~14 (без рубашки/накидки). Якорь «1 талант ≈ 1 гем»
означает: полный билд в один стат на эндгейме ≈ полная прогемовка вторым
комплектом (например, ~420 выносливости с 14 слотов) — сильно, но сопоставимо
с существующей практикой гемовки, и добывается через полную прокачку GA всех
слотов. Ряды 3–4 закрыты явными капами.

## 6. Техническая реализация

### Хранение (acore_characters, pending_db_characters)
```sql
CREATE TABLE IF NOT EXISTS `item_talents` (
  `item_guid`  INT UNSIGNED NOT NULL,
  `owner_guid` INT UNSIGNED NOT NULL,
  `row1` TINYINT UNSIGNED NOT NULL DEFAULT 0,  -- 0 = не выбран, 1..3
  `row2` TINYINT UNSIGNED NOT NULL DEFAULT 0,
  `row3` TINYINT UNSIGNED NOT NULL DEFAULT 0,
  `row4` TINYINT UNSIGNED NOT NULL DEFAULT 0,
  `row5` TINYINT UNSIGNED NOT NULL DEFAULT 0,
  `kills` INT UNSIGNED NOT NULL DEFAULT 0,   -- опыт предмета; очки выводятся из порогов
  PRIMARY KEY (`item_guid`),
  KEY `idx_owner` (`owner_guid`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
Чистка при удалении предмета (hook OnItemRemove/destroy + периодический GC).

### Определения (acore_world, pending_db_world)
```sql
CREATE TABLE IF NOT EXISTS `item_talent_def` (
  `pool`    CHAR(1)  NOT NULL,          -- A..H
  `row`     TINYINT  NOT NULL,          -- 1..5
  `choice`  TINYINT  NOT NULL,          -- 1..3
  `name_ru` VARCHAR(64)  NOT NULL,
  `desc_ru` VARCHAR(255) NOT NULL,
  `effect`  VARCHAR(32)  NOT NULL,      -- STA_PCT, AP_PCT, RATING_CRIT, ...
  `base`    FLOAT NOT NULL DEFAULT 0,
  `per_ilvl` FLOAT NOT NULL DEFAULT 0,  -- значение = ceil(base + per_ilvl*ilvl)
  PRIMARY KEY (`pool`,`row`,`choice`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
Маппинг (class, subclass) → pool — в коде модуля. Data-driven: новые
таланты/тюнинг без ребилда (кроме новых effect-типов).

### Применение статов — БЕЗ spell_dbc

### Опыт предмета (kills)
`PlayerScript::OnCreatureKill` -> `isHonorOrXPTarget(victim)` -> +1 в
in-memory счётчик по GUID каждого надетого предмета; флаш пачкой в
`item_talents.kills` при сохранении игрока/разлогине (не по каждому убийству).
Очки НЕ хранятся отдельно: earned = f(kills, пороги), spent = число ненулевых
rowN, free = earned - spent. Валидация choose: ряд открыт качеством, выбор
пуст, free > 0, nearMaster.

### Перенос при GA-апгрейде
GA пересоздаёт предмет: `DestroyItem` → `StoreNewItem`
(GearAscensionScript.cpp:357-382), там же уже переносятся сокеты
(`applySockets`). В этой точке добавить перенос строки `item_talents` на новый
GUID (UPDATE item_guid). GA — свой модуль, правим напрямую.

### НПЦ-госсип
`AllCreatureScript::CanCreatureGossipHello`, список entry в конфиге

### Протокол аддона (в духе .tmog)
- `.itemtalent list` — все надетые предметы: пул, качество, выборы
- `.itemtalent info <slot>` — доступные таланты предмета в слоте
- `.itemtalent choose <slot> <row> <choice>` — выбрать (требует мастера рядом)
- `.itemtalent reset <slot> <row>` — сброс (требует мастера рядом)
Ответы — SYSTEM-сообщения с префиксом `ITALENT:` для парсинга аддоном.
Русский текст: ASCII '-' и ':', без длинных тире (глифы 3.3.5!).

## 8. Открытые вопросы

- Точные коэффициенты (все значения выше — заготовка под тюнинг).
- Предметы «в левую руку» (class 4 subclass 0) — какой пул.
- GC осиротевших строк item_talents (предмет удалён/продан вендору — buyback?).

  (серверный тултип не трогаем) или зелёные строки через аддон-инжект.
