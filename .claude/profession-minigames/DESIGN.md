# mod-profession-minigames — DESIGN

Мини-игры для профессий: рядом с нативной кнопкой «Создать» появляется кнопка
**«Создать вручную»**, которая открывает тематическую мини-игру. За хорошее
прохождение игрок получает бонус к результату крафта.

Пилот: **Кузнечное дело** (Blacksmithing). Остальные ремёсла — после обкатки.

> **Статус:** Фаза 1 — LIVE на PTR (модуль собран, загружается, кнопка +
> окно работают в игре). Фаза 2 — реализована мини-игра **«Искры на
> заготовке»** (выбрана пользователем 2026-07-09): искры-иконки реагентов
> вспыхивают по одной (горячая ~1.1с), клик по горячей = очки (свежее =
> больше), промах = 0, число искр = число реагентов (кламп 4..8), score =
> средние очки. Чисто клиентская (server не менялся, rebuild не нужен) —
> `.lua` обновлён в репо и в клиенте F:. Фаза 3 (hard-режим + CDN) — ниже.

---

## 1. Ключевое ограничение

Окно профессий (`TradeSkillFrame`) намертво зашито в клиент 3.3.5a — внутрь него
ничего не встроить и поведение нативной «Создать» не переопределить без патча
WoW.exe. Поэтому мини-игра выносится в **клиентский аддон**, а не встраивается в
нативный UI. Инфраструктура addon↔сервер у нас уже отработана (ItemTalentUI,
EnchantDB, TransmogUI, Nemesis) и раздаётся через лаунчер-CDN.

## 2. Модель с двумя кнопками

`TradeSkillFrame` содержит `TradeSkillCreateButton` / `TradeSkillCreateAllButton`
— это обычные близ-фреймы, доступные аддону вне боя. Аддон добавляет свою кнопку
**«Создать вручную»** рядом с нативной.

Нюанс: `Blizzard_TradeSkillUI` грузится по требованию — кнопку вешаем по событию
`TRADE_SKILL_SHOW`, а не при загрузке аддона.

### Режимы (переключатель конфига)

- **Soft (старт):** обе кнопки работают. «Создать» = мгновенно, без бонусов.
  «Создать вручную» = мини-игра + шанс на бонус. Мини-игра опциональна.
- **Hard (позже):** аддон прячет нативные «Создать»/«Создать всё», а серверный
  гейт `OnCheckCast` блокирует крафт-спеллы профессии без валидного score.
  Единственный легальный путь — «Создать вручную». Это и есть «нельзя просто
  клепать предметы». Hard-режим подразумевает обязательный аддон.

## 3. Сквозной поток (soft-режим)

1. Игрок выбрал рецепт в окне профессии → жмёт **«Создать вручную»**.
2. Аддон читает рецепт и реагенты **прямо из клиента**
   (`GetTradeSkillSelectionIndex`, `GetTradeSkillInfo`, `GetTradeSkillReagentInfo`).
   Отсюда же берём иконки реагентов (`GetItemIcon`) — без серверного round-trip.
3. Мини-игра ковки (тематические иконки реальных реагентов).
4. При успехе аддон шлёт `PROFMG:SCORE(spellId, score)`, затем вызывает нативный
   `DoTradeSkill(index)` → ядро крафтит штатно (реагенты, предмет, скилл-ап).
5. Хук `OnPlayerCreateItem` видит отложенный score → применяет награду →
   **сбрасывает** score (чтобы не «протёк» на следующий обычный крафт).

Ботов и нативную «Создать» гейт не трогает (в soft-режиме гейта нет вовсе).

## 4. Модель награды (по score мини-игры)

Пороги — placeholder, тюнятся конфигом. Пол «не хуже обычного крафта» в
soft-режиме: плохой результат = обычный предмет за полную цену (штраф только в
hard-режиме, чтобы был риск).

| score      | Результат                                                        |
|------------|------------------------------------------------------------------|
| `>= 90`    | **+1 уровень качества** (`item_upgrade_chain.next_entry`)         |
| `70..89`   | обычный предмет **+ возврат 30% реагентов**                      |
| `< 70`     | обычный предмет, полный расход (в hard-режиме — минус реагенты)   |

### 4.1 Возврат ресурсов — 30%

Реагенты берём из `SpellInfo::Reagent[]` / `ReagentCount[]`.
Рекомендуемая механика: **каждая единица реагента возвращается с вероятностью
30%** (per-unit roll). Матожидание = ровно 30%, и это корректно работает для
рецептов с 1-2 единицами (детерминированный `floor(count*0.3)` на них давал бы 0).
Альтернатива на будущее — детерминированное округление; выбор за балансом.

### 4.2 +1 уровень качества

Переиспользуем `mod-gear-ascension`. Таблица `item_upgrade_chain`
(`entry → next_entry / prev_entry / to_quality`) уже содержит копии предметов
повышенного качества (8480+ штук).

- Создаётся базовый предмет `X` (ядром через `DoTradeSkill`).
- Если score `>= 90`: `SELECT next_entry FROM item_upgrade_chain WHERE entry = X`.
  Найдено → своп только что созданного предмета на `next_entry` (той же
  swap-механикой, что в GA; enchant-слоты копируются, PERM-слот нет).
- **+1 = ровно один шаг** по цепочке (не прыгаем на 2 ступени).
- **Fallback:** если у предмета нет `next_entry` (нет цепочки / уже максимум) →
  деградируем награду до «возврат 30% реагентов».

### 4.3 Экономический нюанс

Сейчас повышение качества по GA стоит kit'а. Крафт, выдающий `next_entry`
бесплатно за score `>= 90`, — обходной путь к GA-гиру мимо наборов. Поэтому порог
`>= 90` должен быть реально сложным. Мониторить и при необходимости поднять порог
/ добавить кулдаун / ограничить типы предметов.

## 5. Мини-игра ковки (концепт пилота)

Двухфазный QTE на фреймах + `OnUpdate`:

1. **Нагрев:** полоса температуры ползёт вверх, отпустить в рабочей зоне
   (перегрел → минус к score).
2. **Ковка:** N ударов молота, каждый — «останови бегунок в зелёном».

- Итоговый score 0..100 = агрегат точности.
- **Иконки реагентов:** каждый шаг показывает реальную иконку реагента рецепта
  («раскали [слиток]», «вставь [самоцвет]»).
- **Число реагентов задаёт число шагов** ковки → органическое масштабирование
  сложности без ручной настройки на рецепт.

## 6. Addon ↔ Server протокол (addon-канал)

- `PROFMG:HELLO` — рукопожатие при логине; сервер метит сессию `hasAddon`
  (нужно для hard-режима).
- `PROFMG:SCORE(spellId, score, durationMs)` — результат мини-игры перед
  `DoTradeSkill`. Сервер кладёт в per-session stash `{spellId → score}`.
- (hard-режим) сервер → аддон сигнал прятать нативные кнопки.

## 7. Серверная часть (C++)

Новый модуль `modules/mod-profession-minigames/`.

- **Обработчик `PROFMG:SCORE`** — валидация + запись score в per-session stash.
- **`OnPlayerCreateItem(player, item, count)`** — если для `m_spellInfo->Id` есть
  свежий stash-score: применить награду (§4), очистить stash.
- **`OnCheckCast` гейт** — ТОЛЬКО hard-режим: блокировать крафт-спеллы
  разрешённых skill line без валидного stash-score.
- **Фильтр спеллов** — строго по skill line профессии (пилот: Blacksmithing),
  чтобы не задеть классовые `CREATE_ITEM` (маг Conjure, варлок Healthstone,
  ритуалы и т.п.).
- **Античит-минимум** — `durationMs` не короче порога; score в диапазоне.
  Мини-игра клиентская → 100% не закрыть; для PvE приемлемо.

## 9. Фазы

1. **Каркас:** аддон-кнопка «Создать вручную» + рукопожатие + ЗАГЛУШКА мини-игры
   (мгновенно возвращает score) + `PROFMG:SCORE` → награда в `OnPlayerCreateItem`.
   Цель — проверить, что кнопка, `DoTradeSkill`, stash-score и своп/возврат
   работают, боты не ломаются. Гейт НЕ нужен.
2. **Мини-игра:** полноценная ковка (нагрев + удары), иконки реагентов, шаги по
   числу реагентов, привязка score→награда.
3. **Hard-режим + баланс:** гейт `OnCheckCast`, сокрытие нативных кнопок, тюнинг
   порогов/экономики, раздача аддона через лаунчер-CDN.

## 10. Открытые вопросы

- Возврат реагентов: per-unit roll (реком.) vs детерминированное округление.
- Штраф за плохой score в hard-режиме: сколько реагентов сгорает.
- Тиражирование на другие профессии: у алхимии/кулинарии нет GA-цепочки →
  «+1 качество» недоступно, награда = только возврат ресурсов (или доп.
  количество). Пересмотреть модель при расширении.
