## Механика — data-driven, БЕЗ C++ (решение 2026-06-07)

`item_template.Flags = 4` (HAS_LOOT) + `item_loot_template` с одной loot-группой
на сундук. Правый клик → стандартное лут-окно с одной клеткой.

Семантика группы (проверено: `src/server/game/Loot/LootMgr.cpp`,
`LootTemplate::LootGroup::Roll`, ~строка 1292):
- явные шансы роллятся кумулятивно против одного rand(0..100);
- если никто не выпал — равновероятный выбор среди записей с `Chance=0`
  → дроп ГАРАНТИРОВАН, пустых открытий нет;
- групповые шансы НЕ масштабируются `Rate.Drop.*`.

Кодировка (сумма ровно 100):
- **Универсальный** (Entry=110120, GroupId=1): 60 строк Common-клеток
  `Chance=1.4833` + 30 Rare `Chance=0.3333` + 10 Epic `Chance=0`
  (остаток ~1.003% → ~0.1003% каждому эпику — соответствует дизайну 0.1%).
- **Стихийный** (Entry=1101xx, GroupId=1): 6 Common `Chance=11.6667`
  + 3 Rare `Chance=6.6667` + 1 Epic `Chance=0` (остаток ≈ 10%).

`item_loot_template` колонки: Entry, Item, Reference=0, Chance, QuestRequired=0,
LootMode=1, GroupId=1, MinCount=1, MaxCount=1, Comment.

## Шаги реализации

1. **Сверить поля item_template с стоковым лутбоксом** (Docker должен работать):
   `SELECT entry, class, subclass, displayid, Quality, Flags, bonding, stackable,
   lockid, Material FROM item_template WHERE entry IN (44663, 31952, 5760);`
   (Bag of Fishing Treasures 44663 — образец Flags/lockid/class. Ожидаю: class 15,
   subclass 0, Flags 4, lockid 0.)
2. **Выбрать displayid сундуков** (стоковые иконки сундуков/коробок из
   item_template; владельцу показать кандидатов — он выбирает иконки сам).
   Предложение: универсальный покрасивее, стихийные — один общий или по цвету.
3. **Написать `scripts/familiar-gen-chests.ps1`** по образцу familiar-gen-sql.ps1
   (UTF-8 BOM обязателен! читать JSON через [IO.File]::ReadAllText UTF8):
   - читает все 10 `.claude/familiars/*.json` (сортировка по имени файла);
   - эмитит `data/sql/updates/pending_db_world/nemesis_familiars_gacha_chests.sql`:
     item_template (11 шт.) + item_template_locale (ruRU имя + описание с шансами
     в близард-стиле, БЕЗ сокращений) + DELETE/INSERT item_loot_template (210 строк);
   - `-Csv`: upsert 11 строк сундуков в `.claude/dbc/Item_custom.csv`
     (иначе «?» вместо иконок — урок Item.dbc!).
4. Применить через `ptr-sql-apply.ps1 -IKnow`, `ptr-restart.ps1`.
5. **Верификация запросами**: количество loot-строк (110 универсальный?
   нет — 100 строк универсальный + 10×10 стихийные = 210), суммы шансов по
   группам: `SELECT Entry, SUM(Chance), COUNT(*) FROM item_loot_template
   WHERE Entry BETWEEN 110100 AND 110120 GROUP BY Entry;`
   (универсальный: SUM≈98.997/COUNT=100; стихийный: SUM≈90.0/COUNT=10).
6. Владелец: WDBX-мерж `Item_custom.csv` → Item.dbc (11 новых строк) → MPQ →
   очистка WDB → тест `.additem 110120` / `.additem 110100`, открыть пачку,
   убедиться в распределении.
7. Память/статус/коммит.
